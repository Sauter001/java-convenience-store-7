## 📦 도메인 모델

### Product (상품)

- 상품명
- 가격
- 재고 수량 (프로모션 재고 / 일반 재고 분리)
- 적용 가능한 프로모션

### Promotion (프로모션)

- 프로모션 이름
- 구매 수량 (N)
- 증정 수량 (1)
- 시작일
- 종료일

### Order (주문)

- 주문 상품 목록
- 각 상품별 수량

### Receipt (영수증)

- 구매 상품 내역
- 증정 상품 내역
- 금액 정보 (총구매액, 행사할인, 멤버십할인, 내실돈)

### 4. 프로모션 할인 적용

#### 4.1 프로모션 유효성 확인

- [x] 오늘 날짜가 프로모션 기간 내에 포함되는지 확인한다.
- [x] `camp.nextstep.edu.missionutils.DateTimes.now()`로 현재 날짜를 가져온다.

#### 4.2 프로모션 적용 (N+1 형태: 2+1, 1+1 등)

- [x] 프로모션 재고 내에서만 프로모션 혜택을 적용한다.
- [x] 프로모션 재고가 부족하면 일반 재고를 사용한다.
- [x] 동일 상품에 여러 프로모션이 적용되지 않는다.
- **명확화**:
  - 프로모션이 없는 상품은 FullyApplicable로 처리 (확인 메시지 안 뜸)
  - 프로모션 기간 만료된 상품도 동일하게 처리

#### 4.3 추가 증정 안내

- [x] 프로모션 단위(N+1)를 정확히 맞추지 않은 경우, 추가 증정 가능 여부를 안내한다.
- [x] 예시: 2+1 프로모션에서 2개 구매 시 → "1개 더 사면 1개 무료"
- [x] 조건: 프로모션 재고가 충분하고, 현재 수량이 (N+1) 단위에서 N개인 경우만 제안
  - **명확화**: `quantity % setSize == requiredQuantity` 조건 사용
  - 2+1 프로모션: 2개, 5개, 8개 구매 시 제안 (3개, 6개, 9개는 제안 안 함)
- [x] "현재 {상품명}은(는) 1개를 무료로 더 받을 수 있습니다. 추가하시겠습니까? (Y/N)"
- [x] Y 입력 시: 증정 상품 추가 (총 구매 수량 증가)
- [x] N 입력 시: 원래 수량대로 진행 (일부 정가 결제)

#### 4.4 프로모션 재고 부족 안내

- [x] 프로모션 재고가 부족하여 일부 수량을 일반 재고로 결제해야 하는 경우 안내한다.
- [x] 예시: 프로모션 재고 5개, 일반 재고 10개인 상품을 7개 구매 시 → 5개는 프로모션, 2개는 일반 재고
- [x] "현재 {상품명} {수량}개는 프로모션 할인이 적용되지 않습니다. 그래도 구매하시겠습니까? (Y/N)"
- [x] Y 입력 시: 일부 수량 정가 결제 (프로모션 재고 + 일반 재고 사용)
- [x] N 입력 시: 정가 결제해야 하는 수량만큼 제외하고 결제 진행 (프로모션 재고만 사용)
  - **명확화**: N 선택 시 Order의 수량을 promotionQuantity로 조정 (`order.adjustQuantity()`)

#### 4.5 프로모션 나머지 수량 처리

- [ ] 프로모션 단위(N+1)로 나누어떨어지지 않는 나머지 수량이 있는 경우 처리한다.
- [ ] 예시: 2+1 프로모션에서 7개 구매 시 → 6개(2세트) 프로모션 적용 + 나머지 1개 정가
- [ ] 나머지가 1개 이상 N개 미만인 경우, 해당 수량은 프로모션 할인 없이 정가로 계산된다.
- **명확화 - 구현 기준**:
  - **프로모션 재고만으로 충분한 경우**: 4.3 추가 증정 안내 또는 나머지 수량 그대로 정가 계산
  - **프로모션 재고 부족한 경우**: 4.4 재고 부족 안내가 우선 (추가 증정 안내 무시)
  - **증정품 계산**: `(실제 구매 수량 중 프로모션 적용 수량) / setSize`의 몫만큼 증정
  - 예: 2+1에서 7개 주문, 프로모션 재고 7개 → 6개 프로모션(증정 2개) + 1개 정가

### 5. 멤버십 할인 적용

#### 5.1 멤버십 할인 여부 확인

- [ ] "멤버십 할인을 받으시겠습니까? (Y/N)" 출력
- [ ] Y/N 입력 받기

#### 5.2 멤버십 할인 계산

- [ ] 프로모션 미적용 금액의 30%를 할인한다.
- [ ] 멤버십 할인 최대 한도는 8,000원이다.
- **명확화 - 계산 기준**:
  - **프로모션 미적용 금액**: 총 구매 금액 - 프로모션 적용된 금액 (증정품 제외)
  - 예: 콜라 7개(2+1, 1000원) 구매 시
    - 총 구매: 7개 × 1000원 = 7,000원
    - 프로모션 적용: 6개 × 1000원 = 6,000원 (증정 2개)
    - 미적용 금액: 1개 × 1000원 = 1,000원
    - 멤버십 할인: 1,000원 × 0.3 = 300원
  - **계산 공식**: `min((정가 결제 금액) × 0.3, 8000)`

### 6. 재고 관리

#### 6.1 재고 차감

- [ ] 결제된 수량만큼 해당 상품의 재고에서 차감한다.
- [ ] 프로모션 재고 우선 차감 후, 부족분은 일반 재고에서 차감한다.
- **명확화 - 차감 타이밍 및 방식**:
  - **타이밍**: 영수증 출력 직전 (멤버십 할인 확인 후)
  - **차감 로직**:
    1. 프로모션 재고부터 차감 (`min(주문수량, 프로모션재고)`)
    2. 남은 수량은 일반 재고에서 차감
  - 예: 7개 주문, 프로모션 재고 5개, 일반 재고 10개
    - 프로모션 재고: 5개 차감 → 0개 남음
    - 일반 재고: 2개 차감 → 8개 남음

#### 6.2 재고 상태 유지

- [x] 시스템은 최신 재고 상태를 유지한다.
- [x] 다음 고객 구매 시 정확한 재고 정보를 제공한다.

### 7. 영수증 출력

#### 7.1 영수증 구성

```
==============W 편의점================
상품명		수량	금액
콜라		3 	3,000
에너지바		5 	10,000
==============증	정===============
콜라		1
====================================
총구매액		8	13,000
행사할인			-1,000
멤버십할인			-3,000
내실돈			 9,000
```

#### 7.2 영수증 항목 계산

- [ ] **총구매액**: 구매한 상품의 총 수량과 총 금액
- [ ] **행사할인**: 프로모션에 의해 할인된 금액 (증정 상품 가격의 합)
- [ ] **멤버십할인**: 멤버십에 의해 추가로 할인된 금액
- [ ] **내실돈**: 최종 결제 금액 (총구매액 - 행사할인 - 멤버십할인)
- **명확화 - 계산 상세**:
  - **총구매액**: 실제 구매 수량(증정품 제외) × 가격
    - 예: 콜라 3개(2+1) → 총구매액: 3개 × 1000원 = 3,000원 (증정 1개는 수량에 미포함)
  - **행사할인**: 증정품 수량 × 가격
    - 예: 콜라 2+1에서 1개 증정 → -1,000원
  - **멤버십할인**: `min((총구매액 - 프로모션적용금액) × 0.3, 8000)`
    - 프로모션적용금액 = (프로모션 적용 수량 ÷ setSize) × setSize × 가격
  - **내실돈**: 총구매액 - 행사할인 - 멤버십할인

## 🔍 모호한 요구사항 명확화 요약

### 1. 프로모션 나머지 수량 처리 (4.5)
- **문제**: 7개 주문 시 증정품 계산 방법 불명확
- **해결**: `(프로모션 적용 수량 ÷ setSize) × bonusQuantity`로 계산
- **예시**: 2+1에서 7개 주문 → 6개 프로모션(증정 2개) + 1개 정가

### 2. 영수증 총구매액 계산 (7.2)
- **문제**: 증정품이 총구매액에 포함되는지 모호
- **해결**: 증정품 제외, 실제 구매 수량만 총구매액에 포함
- **예시**: 콜라 3개(2+1) → 총구매액 3,000원 (증정 1개 미포함)

### 3. 멤버십 할인 대상 금액 (5.2)
- **문제**: "프로모션 미적용 금액"의 정의 불명확
- **해결**: 총구매액 - 프로모션 적용된 금액 (세트 완성분만)
- **예시**: 7개(2+1) 구매 → 6개는 프로모션, 1개만 멤버십 대상

### 4. 재고 차감 타이밍 (6.1)
- **문제**: 언제 재고를 차감하는지 불명확
- **해결**: 영수증 출력 직전 (멤버십 확인 후)
- **이유**: 사용자가 구매 취소 가능성 고려

### 5. 프로모션 확인 우선순위
- **문제**: 추가 증정과 재고 부족이 동시에 발생 시 어떤 안내가 우선?
- **해결**: 재고 부족 안내(4.4)가 추가 증정(4.3)보다 우선
- **이유**: 실제 구매 가능 여부가 더 중요
